# Prompt تنفيذ الوضع السريع والتفكير المتعمق في Flutter

نفّذ التغييرات التالية في تطبيق رفيق، مع الحفاظ على ملكية المحادثات والموافقات والمرفقات وإعادة المحاولة والمحادثات المؤقتة. الباك إند أصبح يدعم وضعًا سريعًا افتراضيًا، وتفكيرًا متعمقًا للمشتركين في باقة Pro نشطة فقط. اسم الحقل هو `extra_thinking`؛ وهو مستقل تمامًا عن `async` الذي يتحكم في طريقة تسليم الرد.

## عقد الـAPI

استخدم المسارات تحت `/api/v1` والمصادقة الحالية.

### صلاحية الميزة

`GET /chat/usage` يرجع الحقول القديمة بالإضافة إلى:

```json
{
  "can_use_extra_thinking": true,
  "default_response_mode": "fast"
}
```

هذا جزء من الرد وليس بديلًا عن `used`, `limit`, `remaining`, `resets_at`. اعتمد على `can_use_extra_thinking` لحساب المستخدم الحالي. عدم وجود الحقل يعني `false` للتوافق مع السيرفر القديم. بيانات الخطة تتضمن أيضًا `has_extra_thinking`، لكن لا تستخدمها وحدها لإثبات أن اشتراك المستخدم ما زال نشطًا.

### إرسال الرسالة

`POST /conversations/{conversationId}/chat`

```json
{
  "message": "ما هي الأسس الأربعة للتواصل الفعال؟",
  "language": "ar",
  "client_message_id": "uuid-generated-once-for-this-turn",
  "async": true,
  "extra_thinking": false
}
```

- `extra_thinking` اختياري، وقيمته الافتراضية `false`. أرسله Boolean حقيقيًا.
- `true` يطلب التفكير المتعمق، بعد التحقق من البريميوم على السيرفر. لا ترسل اسم موديل أو إعداد reasoning من الموبايل.
- احفظ الرسالة، ومعرّفها، واللغة، والـfeedback، واختيار `extra_thinking` معًا قبل إرسال الطلب. إعادة المحاولة تعيد نفس البيانات ونفس المعرّف. تغيير الوضع مع نفس المعرّف يرجع `409`؛ تغيير الوضع بعد الفشل يحتاج طلبًا جديدًا بمعرّف جديد.
- الرد المعتاد `202` وبداخله `turn`. **قد يرجع `200` و`turn.status=completed` فورًا**، خصوصًا للتحية الأولى. اعرض `turn.message` فورًا ولا تنتظر بدء polling ولا تضف تأخير كتابة مصطنعًا.
- النقل القديم بدون `async` ما زال مدعومًا ويرجع كائن رسالة عند الاكتمال.

كائن `turn` والرسالة المكتملة يتضمنان:

```json
{
  "response_mode": "fast",
  "extra_thinking": false
}
```

القيم الممكنة لـ`response_mode`: `fast` و`deep`. التحيات يمكن أن ترجع `response_type=social`؛ اعرضها كرسائل مساعد طبيعية، ولا تحولها إلى خطأ أو شاشة خاصة. عدم وجود الحقول الجديدة يعني الوضع السريع.

### منع الميزة عن غير المشتركين

السيرفر يرجع `403` قبل حفظ رسالة جديدة أو استهلاك حصتها عند طلب وضع غير مسموح:

```json
{
  "error_code": "EXTRA_THINKING_REQUIRES_PREMIUM",
  "message": "التفكير المتعمق متاح مع اشتراك بريميوم نشط.",
  "retryable": false
}
```

احتفظ بالنص في المحرر، اعرض خيار الترقية أو إرسال الرسالة بالوضع السريع، ولا تدخل في retry تلقائي. إذا انتهى الاشتراك بعد قبول الرسالة وقبل تنفيذها، ستظهر نفس الدلالة في `turn.error.code` مع `retryable=false`. الإرسال السريع بعد ذلك رسالة جديدة بمعرّف جديد؛ لا تغيّر إعدادات الرسالة القديمة بصمت.

### متابعة الطلب

- حافظ على `GET /conversations/{conversationId}/chat/turns/{clientMessageId}` وعلى مسار الإلغاء الحالي.
- اعرض المرحلة الفعلية: `queued`, `checking_context`, `safety_triage`, `turn_planning`, `searching_sources`, `preparing_reply`, `reviewing_reply`, `persisting_reply` ثم `completed` أو `failed` أو `cancelled`.
- اعمل polling واحدًا لكل طلب، كل ثانية أثناء الانتظار، مع backoff عند أخطاء الشبكة. أوقفه فور الحالة النهائية، واستأنفه بعد رجوع التطبيق للشاشة. لا تنشئ POST جديدًا بسبب تأخر polling.
- اعرض المصادر الموجودة في `sources` وربط علامات الاستشهاد بها. لا تخترع مصادر ولا تعتبر `internal_search_performed` وحده دليلًا على أن كل الرد من المكتبة.

## تجربة المستخدم

- الوضع السريع هو الافتراضي للجميع، بما فيهم البريميوم.
- أضف بجانب المحرر اختيارًا واضحًا باسم «تفكير متعمق» / “Extra thinking”، موضحًا أنه قد يستغرق وقتًا أطول. احتفظ بالنص والـfocus عند تغييره.
- للمشترك المسموح له يمكن تفعيل الاختيار. للمستخدم المجاني يظهر مقفولًا مع مسار الترقية الحالي. حدّث الصلاحية عند دخول المحادثة وبعد شراء/تجديد الاشتراك وعند رفض السيرفر.
- عند إرسال الطلب ثبّت اختيار الوضع على تلك الرسالة. يمكن تغيير وضع الرسالة التالية، لكن لا تعِد توصيف الرد الجاري.
- اعرض الرد المكتمل مباشرة؛ لا تضف شاشة انتظار إضافية أو minimum spinner duration. لا تحاكِ streaming لنص لم يصل بعد؛ الباك إند الحالي يستخدم الرد المكتمل مع polling.
- لا تعرض وعودًا بزمن ثابت أو دقة 100%. فحص السلامة مستقل عن الباقة وقد يتطلب وقتًا إضافيًا.

## اختبارات القبول

1. أول تحية تعود `200` مكتملة ويظهر النص فورًا دون polling زائد.
2. رسالة عادية تعود `202` ثم تكتمل؛ لا يتكرر POST ولا تظهر رسالة مكررة.
3. باقة مجانية: لا يمكن إرسال `extra_thinking=true` من الواجهة، ورفض `403` لا يفقد المسودة.
4. بريميوم: الوضع الافتراضي سريع، والتفعيل يرسل `true` ويعرض `deep` في الرسالة.
5. انتهاء الاشتراك أثناء الانتظار يعرض خطأ الميزة ويتيح إرسال طلب سريع جديد.
6. انقطاع الشبكة وإعادة فتح التطبيق يعيدان متابعة نفس المعرّف وبنفس الوضع، دون تبديل flag أو استهلاك رسالة ثانية بالخطأ.
7. الردود القديمة والخوادم التي لا ترجع الحقول الجديدة تظل قابلة للعرض.
8. شغّل اختبارات Flutter والتحليل، وسلّم قائمة الملفات المعدلة ونتيجة اختبار التدفق الفعلي مع الباك إند بعد نشره.
